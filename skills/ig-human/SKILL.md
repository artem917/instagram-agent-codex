# ig-human

Используйте работающие скрипты, а не придуманные оценки. Сначала прочитайте
[runtime guide](references/codex.md) для путей и локальных данных.

## Выберите режим

- `en`: прежний английский; остаётся CLI-режимом по умолчанию. Прочитайте
  [English workflow](references/en.md).
- `ru`: естественный грамотный русский. Литературные кавычки, тире и
  осмысленные абзацы допустимы.
- `ru-social`: единый разговорный русский для любых социальных сетей.
  Обычные двойные кавычки, без длинного тире и пустых строк. Обычный пост не
  разбивается на строку для каждого предложения. Сохраняются содержательные
  списки, многофразовые абзацы, юмор и авторский голос.

Для русского текста выберите `ru`, а для русского поста/Stories/сценария/
комментария в соцсети — `ru-social`, если пользователь не указал иначе.
Вызов CLI без `--mode` по-прежнему английский. Движков по площадкам нет.
Для русского прочитайте [RU workflow](references/ru.md).

```text
python "<skill_dir>/humanize.py" draft.txt --mode ru-social --json
python "<skill_dir>/detect.py" draft.txt --mode ru-social --json
python "<skill_dir>/detect.py" original.txt edited.txt --mode ru-social --json
```

## Порядок работы с RU

1. Прочитайте весь исходник и доступный `voice.md`. Зафиксируйте URL, имена,
   артикулы, числа, отрицания, шутки и утверждения об опыте. Для необычного
   имени/названия используйте повторяемый `--preserve`.
2. Запустите `detect.py`: фрагменты с координатами, русские стилистические
   эвристики и рекомендации. Русского «балла человечности» нет.
3. Запустите `humanize.py`: нормализация, стиль и проверка данных разделены.
   Автоматические словесные изменения ограничены проверенными эквивалентами
   и целыми бессодержательными метафразами. Остальное переписывает Codex с
   пониманием исходного текста, а не regex.
4. При `NEEDS_REWRITE` (exit 3) JSON содержит `text: null` и `candidate` для
   разбора. Это не готовый пост. Текстовый вызов не печатает и не перезаписывает
   файл результата. Разберите неоднозначное тире/литерал вручную. Не заменяйте
   тире дефисом или запятой без понимания синтаксиса.
5. Перепишите только действительно проблемные фразы. Не удаляйте отрицание,
   не приписывайте покупки, личный опыт, отзывы, события или цифры. Не делайте
   грамотный текст примитивным; не добавляйте ошибки «для человечности».
   Один маркер не означает плохую фразу: настоящее спасибо, согласие,
   предупреждение, анафора и полезная инструкция могут остаться.
6. Повторите нормализацию и анализ окончательного текста. При сравнении
   прочитайте `comparison`: проверка данных должна пройти. Сопоставьте смысл
   и факты сами: `semantic_equivalence: UNVERIFIED` не доказывает равенство
   смысла. Не переназначайте те же числа другим фактам.
7. Проверьте оформление, абзацы и авторскую интонацию. Не добавляйте
   обязательный вопрос, CTA, мотивационный вывод или хештеги. Покажите текст
   и оставшиеся обоснованные замечания. Обычно достаточно двух правок;
   не переписывайте по кругу ради исчезновения всех эвристических маркеров.

`ru_lexicon.json` — общий русский словарь. `ru_engine.py` — единственный
RU-движок; `content_guard.py` разделяет токены и защищённые данные.
Параметры площадки необязательны (`--platform-settings file.json`) и только
сообщают о заданных лимитах. Не обрезайте текст и не подключайте аккаунты.

## Границы утверждений

Это проверка оформления и стиля, не определение ИИ-авторства, доказательство
«человечности» или обещание удалить водяные знаки. Emoji с ZWJ, variation
selectors, модификаторами и tag-символами сохраняются. Не удаляйте joiners
по правилу «невидимый значит лишний».

Сложная грамматика, скрытые смысловые повторы и авторский голос требуют
контекстной проверки. Синтетические тесты не заменяют редактора на реальных
текстах. Без Python/shell сообщите UNVERIFIED и выполните явно ручную
редактуру без придуманных отчётов. Публикации или отправки этот навык не делает.
